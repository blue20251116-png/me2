# 스레드 자동발행 대시보드

스레드(Threads) 공식 API로 글을 예약 발행하고, 발행된 글의 조회수를 자동 수집해서
오늘 발송 예정/완료 건수, 시간대별 발행 현황, 조회수 합계를 보여주는 대시보드입니다.
쿠팡파트너스 Open API와도 연동되어 있어 키워드 검색만으로 상품 사진·가격·파트너스 링크를
자동으로 가져와 글을 채울 수 있습니다.

## 1. 로컬에서 먼저 확인해보기

```
npm install
npm start
```

브라우저에서 http://localhost:3000 접속. (아직 계정 연결은 안 된 상태 — 화면 구조만 먼저 확인 가능)

## 2. 쿠팡파트너스 Open API 키 발급 (건우님이 직접 하셔야 하는 부분)

쿠팡파트너스는 이미 가입되어 있다는 전제로:

1. https://partners.coupang.com 로그인 → 상단 메뉴 또는 계정 설정에서 **"Open API"** / "개발자 센터" 메뉴 찾기
2. Access Key / Secret Key 발급받기 (즉시 발급되는 경우가 많음, 별도 심사 없을 수 있음)
3. 대시보드 **연결 설정** 탭 → "쿠팡파트너스 API 연결"에 Access Key/Secret Key 입력 → 저장

이렇게 하면 **글 예약** 탭에서 키워드로 상품을 검색하면 파트너스 링크·상품 사진·가격이
한번에 채워집니다. (링크를 직접 붙여넣는 기존 방식도 계속 사용 가능하며, 이 경우엔 og:image
스크래핑으로 사진만 보조로 가져옵니다.)

⚠️ 검색 API는 호출 빈도 제한이 있습니다(체감상 시간당 10회 수준이라는 사용기가 있음, 정책은
계속 바뀔 수 있음). 검색을 너무 자주 반복하지 마시고, 한 번 검색한 결과에서 필요한 상품을
바로 선택해서 쓰는 걸 권장합니다.

## 3. 스레드(Threads) Meta 개발자 앱 만들기 (건우님이 직접 하셔야 하는 부분)

1. https://developers.facebook.com 접속 → 로그인 (본인 스레드 계정과 연결된 Instagram/Facebook 계정 필요)
2. "내 앱" → "앱 만들기" → 유형은 "기타" 또는 "비즈니스" 선택
3. 앱 대시보드에서 "제품 추가" → **Threads API** 추가
4. Threads API 설정 화면에서:
   - **Threads App ID**, **Threads App Secret** 확인 (연결 설정 탭에 입력할 값)
   - **유효한 OAuth 리디렉션 URI**에 배포 주소 + `/auth/callback` 등록
     - 예: `https://내앱주소.up.railway.app/auth/callback`
     - 로컬 테스트 시엔 `http://localhost:3000/auth/callback`
5. 앱이 "개발 모드"일 때는 본인 계정(테스트 사용자로 등록된 계정)만 로그인 가능합니다.
   본인 계정만 쓸 거면 개발 모드로도 충분합니다 (별도 심사 불필요).

## 4. 앱에 연결 정보 입력

배포 후 대시보드의 **연결 설정** 탭에서 App ID / App Secret / Redirect URI 입력 → 저장 →
"스레드 계정으로 연결하기" 클릭 → 스레드 로그인 화면에서 권한 동의 → 자동으로 대시보드로 복귀.

연결되면 상단에 "연결됨 · @계정명"이 표시됩니다.

## 5. 배포 (24시간 자동 발행이 되려면 서버가 계속 켜져 있어야 함)

로컬 PC를 계속 켜둘 게 아니라면 아래 중 하나에 올리는 걸 추천합니다.

- **Railway** (railway.app) — Node 프로젝트 그대로 올리면 자동 인식, 무료 크레딧 있음
- **Render** (render.com) — Web Service로 배포, 무료 플랜은 슬립 모드 있으니 유료 권장
- 이전에 쓰시던 **Replit**도 가능 (Always On 옵션 필요)

배포 시 환경변수(`.env.example` 참고)로 App ID/Secret/Redirect URI를 넣어도 되고,
첫 배포 후 웹 화면의 "연결 설정" 탭에서 직접 입력해도 됩니다.

⚠️ SQLite 파일(`db/scheduler.db`)에 예약 글과 토큰이 저장됩니다. 무료 플랜 중에는
재배포할 때마다 파일시스템이 초기화되는 곳도 있으니(Render 무료 플랜 등), 배포 전에
호스팅의 "영구 디스크/볼륨" 옵션을 확인하세요. Railway는 기본 지원합니다.

## 6. 사용 흐름

1. **글 예약** 탭 상단의 **쿠팡파트너스 상품 검색**에서 키워드 검색 → 원하는 상품 "선택"
   → 파트너스 링크·상품 사진·상품명이 자동으로 채워짐 (가장 추천하는 방법)
   - 또는 이미 갖고 있는 링크를 **쿠팡파트너스 링크** 입력란에 직접 붙여넣어도 됨
     (이 경우 og:image 스크래핑으로 사진만 보조로 가져옴, API 검색보다 덜 안정적)
2. 본문 작성 + 발행 예정 시각 입력 → 예약 등록
3. 서버가 1분마다 예정 시각이 지난 글을 자동 발행 (`scheduler.js`)
4. **링크가 있는 경우**, 본문 발행 3초 후 자동으로 그 글에 답글(댓글)을 달아
   "쿠팡 파트너스 활동의 일환..." 안내문구 + 링크를 등록합니다 (본문에는 링크가 들어가지 않음)
   - 안내문구 템플릿은 **연결 설정** 탭에서 직접 수정 가능 (`{link}` 자리에 실제 링크 삽입)
   - 글 예약 시 "댓글로 자동 등록" 체크를 해제하면 댓글은 달지 않음
5. 발행 후 10분마다 조회수/좋아요 등 인사이트를 자동 갱신
6. **대시보드** 탭에서 오늘 현황 확인, **전체 글 목록** 탭에서 댓글 등록 성공/실패 여부 확인

## 7. Node.js 버전 요건

DB에 별도 설치 없는 **Node.js 내장 SQLite 모듈**을 사용합니다 (네이티브 빌드 불필요 —
호스팅에서 흔히 겪는 빌드 실패 문제를 피하기 위한 선택). **Node.js 22.5 이상**이 필요합니다.
Railway/Render에서 Node 버전을 지정할 수 있으면 22 이상으로 맞춰주세요.

## 8. 알아두면 좋은 제약

- 스레드 계정당 **하루 250건**까지 발행 가능 (Meta 정책)
- 쿠팡파트너스 상품검색 API는 호출 빈도 제한이 있음 — 검색을 너무 자주 반복하지 말 것
- 링크 직접 붙여넣기로 이미지를 가져오는 스크래핑 방식은 쿠팡이 봇 접근을 차단하거나
  페이지 구조를 바꾸면 실패할 수 있습니다 — 이 경우 이미지 URL을 직접 입력하면 됩니다
  (API 검색을 쓰면 이 문제 자체가 없음)
- 이미지 첨부 시 `image_url`은 외부에서 접근 가능한 공개 URL이어야 함 (직접 업로드 불가, 링크만 가능)
- Threads 장기 액세스 토큰 유효기간은 60일 — 만료 전 갱신 로직은 `threadsApi.js`의
  `refreshLongLivedToken`에 준비되어 있음 (현재는 자동 스케줄 미적용, 필요하면 추가 가능)
- 계정마다 Threads 연결은 처음 한 번만 하면 됩니다 (계정별 OAuth) — 이후 계정 칩을 눌러
  전환할 때는 재연결 없이 바로 그 계정 기준으로 화면이 바뀝니다. 여러 계정 동시 관리는
  정식으로 지원됩니다 (11번 항목 참고)

## 9. AI 글 자동 생성 (선택)

"글 예약" 탭 본문 입력란 위의 **"✨ AI로 글 써주기"** 버튼을 누르면, 광고 느낌 없는
캐주얼한 스레드 본문을 자동으로 써줍니다. 상품 검색으로 고른 상품이나 링크로 가져온
상품 정보를 바탕으로 작성됩니다.

**사용하려면 Anthropic API 키가 필요합니다:**
1. https://console.anthropic.com 가입/로그인
2. API Keys 메뉴에서 새 키 발급 (`sk-ant-...`로 시작)
3. 대시보드 **연결 설정** 탭 → "AI 글 생성" 섹션에 붙여넣고 저장
4. 호출당 소액 과금됩니다 (콘솔에서 사용량/잔액 확인 가능)

이 키가 없어도 나머지 기능(예약 발행, 댓글 자동 등록, 상품 검색)은 정상 작동합니다 —
이 버튼만 못 씁니다.

## 10. 내 사진/영상 직접 첨부 (선택)

검색이나 스크래핑으로 자동으로 채워진 사진이 마음에 안 들면, "글 예약" 탭의
**"📎 내 사진/영상 직접 첨부"** 버튼으로 갖고 계신 사진이나 영상을 올려서 붙일 수 있습니다.
jpg/png/gif/webp 이미지와 mp4/mov 영상을 지원하며, 최대 200MB까지 가능합니다.

- 업로드하면 자동으로 이미지 URL(또는 영상 URL) 칸이 채워지고 미리보기가 뜹니다
- 마음에 안 들면 미리보기 위의 **"✕ 첨부 삭제"**를 눌러 지우고 다시 올릴 수 있습니다
- 영상은 스레드 서버에서 인코딩 처리 시간이 걸려서, 발행 시 최대 1분 정도 대기 후 올라갑니다
- 업로드한 파일은 서버(`uploads` 폴더)에 저장됩니다. Railway 무료 플랜처럼 재배포마다
  파일시스템이 초기화되는 환경에서는 재배포 시 기존 업로드 파일이 사라질 수 있으니,
  중요한 파일은 따로 보관해두는 걸 권장합니다 (영구 디스크/볼륨을 설정하면 유지됩니다)

## 10-1. 영상 프레임(장면) 추출 (선택)

직접 올린 영상을 그대로 게시하는 대신, 영상 속 여러 장면을 사진으로 추출해서 그중 원하는
장면을 Threads 게시 이미지로 쓸 수 있습니다. **YouTube 영상이 아니라 내가 직접 올린
영상에서만 동작하는 기능**입니다. 기본적으로는 AI가 베스트컷을 추천해주지만(아래
"AI 베스트컷 추천" 참고), 꺼두면 순수 수동 선택만으로도 동일하게 사용할 수 있습니다.

흐름: 영상 업로드 → "영상에서 사진 추출" 선택 → 여러 장면 후보 표시(+AI 추천) → 최대 2장
선택 → "게시 이미지 구성"(추출 사진만 / 추출 사진 + 상품 이미지 / 기존 상품 이미지만)
선택 → 예약/발행. **최대 2장인 이유는 현재 Threads 게시 로직이 이미지 2장(캐러셀)까지만
지원하기 때문입니다.**

**FFmpeg/FFprobe 필요** — 서버에 이 두 프로그램이 설치되어 있어야 프레임 추출 기능이
동작합니다. 설치되어 있지 않아도 **서버 자체는 정상 기동**하고, 나머지 기능(예약 발행,
AI 글쓰기, 쿠팡 검색, YouTube 소싱 등)도 전부 정상 작동합니다 — 이 기능만 "현재 서버에서
영상 프레임 추출 기능을 사용할 수 없습니다" 오류를 반환합니다.

Railway는 기본적으로 FFmpeg를 포함하지 않습니다. Nixpacks 빌더를 쓰는 경우 저장소 루트의
`nixpacks.toml`에 아래처럼 추가하면 빌드 시 함께 설치됩니다 (이 저장소에는 이미 포함되어
있습니다):

```toml
[phases.setup]
nixPkgs = ["ffmpeg"]
```

다른 빌더(Docker 등)를 쓰신다면 해당 이미지에 `ffmpeg`/`ffprobe`를 직접 설치해주셔야
합니다. 설치 경로가 `ffmpeg`/`ffprobe`(PATH 안)가 아니라면 환경변수로 경로를 지정할 수
있습니다:

```
FFMPEG_PATH=/usr/bin/ffmpeg
FFPROBE_PATH=/usr/bin/ffprobe
```

**⚠️ Railway 파일시스템은 영구 저장소가 아닙니다.** 추출된 프레임 이미지도 업로드 파일과
마찬가지로 `uploads/frames/` 아래에 저장되는데, 재배포나 재시작이 일어나면 이 파일들도
함께 사라질 수 있습니다. 예약 시간이 많이 남은 글에 추출한 프레임을 걸어두면, 그 사이
재배포가 발생할 경우 발행 시점에 이미지가 없어질 위험이 있습니다. 트래픽이 늘어나면
Cloudflare R2, S3 호환 스토리지, Supabase Storage 같은 영구 오브젝트 스토리지로 옮기는
것을 권장합니다 (이번 작업에서는 도입하지 않았습니다).

기타:
- 계정마다 동시에 영상 1개만 처리할 수 있습니다 (같은 계정이 버튼을 연타해도 중복 작업이
  생기지 않음)
- 선택하지 않은 장면은 영상을 교체하거나 첨부를 삭제할 때 자동으로 정리됩니다. 선택해서
  예약글에 사용된 장면은 그 글이 발행되기 전까지 지워지지 않습니다
- 다른 회원이 내 영상이나 추출된 장면에 접근/삭제할 수 없습니다 (계정별로 완전히 분리된
  폴더에 저장됨)

### AI 베스트컷 추천 (선택)

프레임을 추출하면 "AI 베스트컷 자동 추천" 체크박스가 기본으로 켜져 있어서, 추출 직후
자동으로 OpenAI Vision이 각 장면을 분석해 게시하기 좋은 순서로 추천해줍니다. **사람의
실제 신원을 식별하거나 유명인 이름을 추측하지 않습니다** — "사람이 잘 보이는 장면인지",
"제품이 잘 보이는지", "흔들렸는지" 같은 화면 품질만 평가합니다. 영상에 유명인이 등장해도
자동으로 제외하지 않고, 다만 사람이 잘 보이는 장면(인물/후킹)으로 분류해 후보에 올릴 수
있습니다 — 최종 선택은 항상 사용자가 합니다.

- 관리자 공용 OpenAI 키를 그대로 재사용합니다 (회원별 키 불필요)
- 프레임 여러 장을 **한 번의 API 요청**으로 묶어서 분석합니다 (프레임 수만큼 호출하지 않음)
- 분석에 실패해도(키 없음/네트워크 오류/응답 파싱 실패 등) 전체 기능이 죽지 않고
  "AI 추천 없이 수동 선택 가능" 상태로 조용히 넘어갑니다

## 12. YouTube 콘텐츠 소싱

"글 예약" 탭의 **"🔥 관련 쇼츠 찾기"** 패널에서 상품명으로 관련 YouTube 짧은 영상을
검색해서 콘텐츠 소재로 참고할 수 있습니다. **영상을 다운로드하는 기능이 아니라,
제목/설명/조회수/채널 정보를 참고 소재로만 활용하는 탐색 기능입니다.**

- 관리자가 `/admin` 페이지의 "서비스 공용 API 설정"에 **YouTube Data API Key**를
  한 번 입력해두면 모든 회원이 공용으로 사용합니다 (일반 회원은 이 키를 볼 수 없습니다)
- 쿠팡 상품검색에서 상품을 선택하면 상품명이 쇼츠 검색창에 자동으로 채워지고, 직접
  수정도 가능합니다
- 정렬 기준은 **상품 관련도 / 조회수 높은 순 / 최신순** 3가지를 지원합니다
- 검색 결과 카드에서 **"이 소재 사용"**을 누르면 그 영상의 제목/설명이 "선택한 콘텐츠
  소재"로 표시되고, 이후 "AI로 글 써주기"를 누르면 그 소재를 참고자료로 삼아 글을
  만듭니다 — 영상 문장을 그대로 베끼지 않고, 영상 제작자나 사용자 본인이 실제로 제품을
  써봤다고 단정하지 않도록 프롬프트에서 제한합니다
- 이 키가 없어도 나머지 기능(예약 발행, AI 글 생성, 쿠팡 상품 검색 등)은 전부 정상
  작동합니다 — "관련 쇼츠 찾기" 기능만 "관리자가 YouTube API Key를 아직 설정하지
  않았습니다" 안내와 함께 비활성 상태가 됩니다

### 완전자동화(오토파일럿)에서도 자동으로 소재를 찾아줍니다

"🚀 완전 자동발행" 패널에 **"관련 쇼츠 콘텐츠 참고"** 옵션(기본 ON)과 탐색 방식(상품
관련도 우선 / 조회수 높은 콘텐츠 우선 / 최신 콘텐츠 우선)이 있습니다. 켜져 있으면
오토파일럿이 상품을 고를 때마다:

1. 상품명에서 브랜드/모델/규격을 뺀 짧은 검색어를 AI가 만들고
2. 그 검색어로 YouTube를 검색해서 후보를 모으고
3. 상품 관련성(가중치 50) · 조회수(20) · 최근성(15) · 영상 활용성(15)으로 점수를 매겨
   가장 적합한 영상 1개를 자동으로 골라 글 소재로 씁니다

**YouTube Key가 없거나, 검색이 실패하거나, 결과가 없어도 오토파일럿은 절대 멈추지
않습니다** — 그 경우 그냥 기존 상품 기반 글 생성으로 조용히 넘어갑니다. 옵션을 끄면
YouTube API를 아예 호출하지 않고 기존 방식 그대로 동작합니다.

### 완전자동화가 수동으로 골라둔 영상 프레임을 재사용 (선택, 기본 OFF)

"🚀 완전 자동발행" 패널의 **"업로드 영상 프레임 자동 사용"** 옵션을 켜두면, 예전에 수동으로
영상을 올리고 프레임을 골라서 게시했던 상품과 이름이 겹치는 상품을 오토파일럿이 다시 고를
때, 그때 골랐던 이미지 조합(프레임+상품 이미지 등)을 다시 검색 없이 재사용합니다.

- 새로 영상을 찾아오거나 프레임을 다시 추출하지 않습니다 — **수동 흐름에서 이미 완료된
  선택 결과만** 재사용합니다 (`media_sources`라는 최소한의 매핑 테이블에 상품명↔이미지
  조합만 기억해둡니다)
- 상품명이 겹치지 않으면(전혀 관련 없는 영상) 재사용하지 않고 기존 상품 이미지를 씁니다 —
  아무 영상이나 상품과 무작정 조합하지 않습니다
- Railway 재배포 등으로 저장해둔 프레임 파일이 실제로 사라졌으면, 사용 직전에 파일 존재
  여부를 확인해서 없으면 조용히 기존 상품 이미지로 넘어갑니다
- 기본값은 **OFF**입니다 — 켜기 전까지는 완전자동화가 항상 기존 상품 이미지만 사용합니다

**이미지 선택 우선순위:** 연결된 미디어(프레임 조합) 있음 → 사용 / 없음 → 기존 쿠팡
상품 이미지 사용. 이미지 관련 문제로 글 생성 자체가 실패하는 일은 없습니다.
